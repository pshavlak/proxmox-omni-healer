## Фаза 1: Базовая безопасность и стабильность 🔒
*Приоритет — срочно. Цель: обеспечить минимальную защиту и надёжность работы сайта в production.*

### 1.1 Настроить HTTPS (SSL/TLS)
- [ ] Дождаться распространения DNS (домен делегирован на NS Cloudflare).
- [ ] Выпустить сертификат через acme.sh с DNS-01 challenge (Cloudflare API).
- [ ] Настроить автообновление сертификата (cron / systemd timer).
- [ ] В nginx на VPS добавить редирект с HTTP на HTTPS.
- [ ] Включить HSTS, OCSP stapling.

### 1.2 Настроить UFW и восстановить SSH
- [ ] На LXC контейнере: `ufw allow 22/tcp`.
- [ ] `ufw default deny incoming`, разрешить 22 (SSH), 80, 443.

### 1.3 Добавить health check и мониторинг
- [ ] Создать эндпоинт `/health` в `app.py`:
  ```python
  @app.get("/health")
  def health():
      return {"status": "ok"}
  ```
- [ ] Настроить UptimeRobot или аналог на проверку `/health` раз в 5 минут.
- [ ] Настроить уведомления (email/telegram) при недоступности.

### 1.4 Rate limiting для всех write-эндпоинтов
- [ ] Распространить существующий rate limiter на:
  - `/api/feedback`
  - `/api/media/upload`
  - `/api/settings`
  - `/api/pages/{page_id}/blocks`
- [ ] Рассмотреть подключение `slowapi` для более гибкого управления.

### 1.5 Закрыть debug mode в production
- [ ] В `app.py`:
  ```python
  debug = os.getenv("DEBUG", "false").lower() == "true"
  ```
- [ ] `uvicorn.run(..., reload=False)`.

## Фаза 2: Улучшение функционала 🛠️
*Приоритет — средний. Цель: добавить востребованные функции и повысить удобство.*

### 2.1 Полнотекстовый поиск по сайту
- [ ] Создать виртуальную таблицу FTS5 в SQLite (миграция `database.py`).
- [ ] Индексировать страницы (title, content из блоков).
- [ ] Эндпоинт: `GET /api/search?q=...`.
- [ ] Форма поиска в `base.html` / `header.html`.
- [ ] Асинхронный поиск на клиенте (JS).

### 2.2 Генерация sitemap.xml и robots.txt
- [ ] `GET /sitemap.xml` — динамический XML со списком опубликованных страниц.
- [ ] `GET /robots.txt` — указать sitemap, запретить `/admin/`, `/api/`.
- [ ] В `base.html` добавить `<link rel="sitemap" ...>`.

### 2.3 Кеширование ответов
- [ ] Nginx: кеш статики (css, js, jpg, png, gif) — `expires 7d`.
- [ ] Для публичных страниц добавить `Cache-Control: public, max-age=3600`.
- [ ] Рассмотреть `fastapi-cache` для кеширования эндпоинтов `/api/content/pages` и `/api/content/recent`.

### 2.4 Версионирование блоков (history)
- [ ] Создать таблицу `blocks_history`: `id`, `block_id`, `config_snapshot`, `created_at`, `user_id`.
- [ ] При сохранении блока (`PUT /api/pages/{page_id}/blocks`) сохранять предыдущую версию.
- [ ] Эндпоинты: `GET /api/blocks/{block_id}/history`, `POST /api/blocks/{block_id}/restore/{version_id}`.
- [ ] В админ-панель добавить кнопку "История".

### 2.5 CAPTCHA для формы "Предложить новость"
- [ ] Подключить Cloudflare Turnstile (бесплатно, без капчи для пользователей).
- [ ] В `suggest_modal.html` добавить `<div class="cf-turnstile" ...>`.
- [ ] На сервере (`api_suggest`) проверять токен через `POST /siteverify`.

### 2.6 Загрузка нескольких файлов в медиа-центр
- [ ] В `api_upload_media`: `UploadFile` → `List[UploadFile] = File(...)`.
- [ ] На клиенте (админка) drag-and-drop + множественный выбор.
- [ ] Уникальные имена файлов, запись в БД.

### 2.7 Виджеты на главной (последние новости, случайное фото)
- [ ] Сервер: `GET /api/content/recent` (уже есть), `GET /api/content/random-media`.
- [ ] В `index.html` динамическая подгрузка через AJAX.
- [ ] Placeholder при отсутствии данных.

## Фаза 4: Операционная работа и автоматизация ⚙️
*Цель: снизить ручной труд и повысить надёжность.*

### 4.1 Резервное копирование
- [ ] Ежедневный cron:
  - Бэкап SQLite (`cp zolotarevka.db backup/` + VACUUM).
  - Бэкап `static/uploads/`.
- [ ] Отправка на внешнее хранилище (restic / rsync → Hetzner Storage Box).
- [ ] Хранение за 30 дней.

### 4.2 Мониторинг SQLite
- [ ] Скрипт проверки размера `zolotarevka.db`.
- [ ] При превышении 1 ГБ — VACUUM и архивация.
- [ ] Алерт в систему мониторинга.

### 4.3 Автоматизация деплоя
- [ ] Makefile:
  - `make deploy` — копирование файлов на сервер (scp/rsync).
  - `make restart` — перезапуск uvicorn через systemd.
- [ ] GitHub Actions: CI/CD при пуше в main.

### 4.4 Обновление документации
- [ ] В wiki (`SCHEMA.md`) обновить архитектуру, добавить новые эндпоинты.
- [ ] Создать `CHANGELOG.md` на основе `log.md`.
- [ ] README для новых разработчиков (локальный запуск).

### 4.5 Миграция со старого WordPress-сайта
- [ ] Написать скрипт импорта контента (типы записей, изображения) в новую БД.
- [ ] Импортировать в `media` и `suggestions`.
- [ ] После успешного импорта — редирект со старого URL на новый (nginx).
