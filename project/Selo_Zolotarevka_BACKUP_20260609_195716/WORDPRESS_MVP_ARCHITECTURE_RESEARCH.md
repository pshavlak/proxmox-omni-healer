# Анализ и архитектура WordPress MVP для сайта села Золотаревка

Дата: 26.05.2026
Issue: YUP-3

## 1) Цель MVP
Запустить управляемый жителями информационный портал села на WordPress с базовым редакционным потоком, без кастомного бэкенда и с минимальным техническим долгом.

Критерий успеха MVP:
- Публикация новостей по ключевым направлениям (школа, детсад, совхоз, спорт, жизнь села)
- Актуальный блок матчей/результатов
- Форма «Предложить новость» с премодерацией
- Рабочие роли редакторов по направлениям
- Устойчивая производительность и резервное копирование

## 2) Рекомендованная архитектура (MVP)

### 2.1 Технический стек
- CMS: WordPress 6.x
- PHP: 8.2+
- DB: MariaDB 10.6+ (или MySQL 8.0+)
- Веб-сервер: Nginx + PHP-FPM
- Кэш: FastCGI cache + page cache plugin
- Медиа: локально на старте, переход на object storage при росте

### 2.2 Структура слоев
- Тема: child theme на базе легкой parent-theme (Astra/GeneratePress)
- Контент-модель: стандартные записи + кастомные типы контента
- Кастомизация: ACF (поля), CPT UI (при необходимости) или регистрация CPT в небольшом mu-plugin
- Интеграции: формы, SEO, антиспам, кеш, бэкапы

### 2.3 Рекомендованный принцип
Критичные бизнес-настройки (CPT, таксономии, ключевая логика) хранить в коде (`mu-plugin`), а не только в UI, чтобы упростить перенос между стендами.

## 3) Контент-модель

### 3.1 Типы записей
- `post` — общие новости и объявления
- `sports_match` — матчи и результаты
- `sports_player` — профиль игрока
- `bulletin` — доска объявлений
- `farm_vacancy` — вакансии совхоза
- `village_event` — события ДК/села

### 3.2 Таксономии
- `sector`: school, kindergarten, farm, sport, village-life
- `sport_type`: football, volleyball, chess, other
- `bulletin_type`: buy, sell, service

### 3.3 Базовые поля (ACF)
- `sports_match`: дата/время, соперник, домашний/гостевой, счет, авторы голов, статус
- `sports_player`: позиция, номер, фото, краткая био
- `bulletin`: срок актуальности, контакты, тип объявления
- `village_event`: дата, место, краткая программа

## 4) Информационная архитектура страниц
- Главная: hero + важные объявления + последние новости + ближайший матч + афиша
- Разделы: школа, детсад, совхоз, спорт, жизнь села, медиа
- Спорт: календарь, турнирная таблица (ручная MVP-версия), состав, фото
- Медиа: галереи по рубрикам/событиям

Навигация:
- Верхнее мега-меню с 3 группами: Организации, Спорт, Жизнь села
- Быстрые плитки с главной на ключевые разделы

## 5) Роли и редакционный процесс

### 5.1 Роли
- Администратор: полное управление
- Главный редактор: публикация по всем разделам
- Редактор школы
- Редактор спорта
- Редактор совхоза
- Модератор: комментарии и входящие материалы

### 5.2 Workflow
1. Житель отправляет новость через форму
2. Материал попадает в `draft/pending`
3. Модератор проверяет вложения/спам
4. Профильный редактор дополняет и отправляет на публикацию
5. Главный редактор/админ публикует

## 6) Набор плагинов для MVP
Минимальный стек:
- Формы: WPForms (или Contact Form 7)
- Антиспам: Antispam Bee / Akismet
- SEO: Rank Math или Yoast SEO
- Кеш: WP Super Cache (или аналог для вашего хостинга)
- Бэкапы: UpdraftPlus
- Безопасность: Limit Login Attempts Reloaded + базовый hardening
- Медиа-галерея: Modula (или нативный Gutenberg на старте)

Примечание:
- Для футбольной статистики MVP проще начать с `sports_match` + шаблонов, без тяжелых спортивных плагинов.

## 7) Безопасность и эксплуатация
- Обязательный SSL
- 2FA для админов/редакторов
- Ограничение попыток входа
- Автообновления минорных версий WP и плагинов
- Ежедневные бэкапы БД + еженедельные полные бэкапы
- Наблюдение за uptime и ошибками PHP

## 8) Производительность
- WebP для изображений
- Ленивая загрузка медиа
- Кеш страниц и браузерный кеш
- Ограничение веса hero-баннера
- Целевая метрика: LCP <= 2.8s на мобильных в типовых условиях

## 9) План внедрения (2 недели MVP)
- День 1-2: инфраструктура, WP, базовая тема, безопасность
- День 3-4: контент-модель (CPT/таксономии/поля), меню
- День 5-7: шаблоны разделов и главной
- День 8-9: формы, модерация, роли, комментарии
- День 10: SEO, кеш, медиа-оптимизация
- День 11-12: первичное наполнение, UAT с редакторами
- День 13-14: запуск и стабилизация

## 10) Риски и смягчение
- Риск: перегрузка плагинами
  - Мера: ограничить стек, всё критичное держать в `mu-plugin`
- Риск: низкое качество контента от разных редакторов
  - Мера: шаблоны публикаций + чек-лист модерации
- Риск: медленная загрузка из-за фото
  - Мера: лимиты размеров и автоконверсия в WebP
- Риск: спам через формы
  - Мера: антиспам + rate limiting + ручная премодерация

## 11) Что взять из текущего HTML-прототипа
Из папки `site/` переносим:
- информационную архитектуру страниц
- тексты блоков и разделов
- состав модулей главной (плитки, матч-виджет, лента)

В WordPress перенос делается через шаблоны темы + Gutenberg-блоки, без копирования статической структуры 1:1.

## 12) Вывод
WordPress подходит для MVP Золотаревки: быстрый запуск, понятный редакционный процесс, низкий порог администрирования. Рекомендуется запускать MVP на минимальном plugin-stack, с контент-моделью в коде (`mu-plugin`) и поэтапным усложнением только после первых 4-6 недель эксплуатации.
