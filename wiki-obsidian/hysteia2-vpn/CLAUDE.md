# LLM Wiki — Hysteia2 VPN

Этот wiki поддерживается LLM-агентом по методологии Karpathy's LLM Wiki.

## Структура

```
hysteia2-vpn/
├── CLAUDE.md             # Инструкция для LLM-агента (этот файл)
├── SCHEMA.md             # Таксономия тегов, конвенции фронтматера
├── index.md              # Каталог всех страниц с краткими описаниями
├── log.md                # Хронология изменений (append-only)
├── sources/              # Исходные документы (read-only, не редактировать)
│   └── Hysteria2/        # Исходные файлы проекта Hysteria2
│       └── README.md
├── entities/             # Структурированные страницы сущностей
│   ├── hysteria-2-server
│   ├── cascade-server
│   ├── hist-yupiterpro-ru
│   ├── wireproxy
│   └── xray-server
├── concepts/             # Структурированные страницы концепций
│   ├── hysteria-2-protocol
│   ├── infrastructure-architecture
│   ├── acl-routing
│   ├── socks5-cascade
│   ├── user-management
│   └── wireproxy-memory-leak
├── raw/                  # Будущие источники (статьи, PDF, транскрипты)
│   ├── articles/
│   ├── papers/
│   ├── transcripts/
│   └── assets/
├── *.md                  # Плоские страницы (оригинальная версия вики)
└── comparisons/          # (будущее) Сравнения
└── queries/              # (будущее) Результаты запросов
```

## Операции

### Ingest (загрузка источника)
1. Положи файл в `sources/` или укажи URL
2. Прочти и осмысли содержание
3. Обсуди ключевые моменты с пользователем
4. Интегрируй информацию: создай/обнови страницы, проставь `[[связи]]`
5. Запиши в `log.md`

### Query (запрос)
- Сначала просмотри `index.md` и релевантные страницы
- Ответь с ссылками на страницы wiki (`[[страница]]`)
- Если ответ требует нового знания — создай страницу

### Lint (поддержка)
Периодически проверяй:
- Нет ли страниц без входящих ссылок (сироты)
- Нет ли устаревших утверждений
- Нет ли противоречий между страницами
- Обновляй `index.md`

## Правила
- Страницы должны быть краткими, плотными, информативными
- Активно используй `[[вики-ссылки]]` для связывания
- Источники в `sources/` не редактировать — только читать
- Сложные темы разбивай на несколько страниц
- Каждая страница отвечает за одну концепцию
- При изменениях — обновляй `log.md`
- Новые страницы в `entities/` и `concepts/` должны иметь YAML фронтматер
- Теги для фронтматера брать из `SCHEMA.md`
