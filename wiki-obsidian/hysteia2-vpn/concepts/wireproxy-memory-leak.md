# WireProxy Memory Leak

**Известная проблема** WireProxy v1.0.9 — утечка памяти на [[cascade-server]].

## Характеристики

| Параметр | Значение |
|----------|----------|
| **Скорость утечки** | ~20 MB/час |
| **Время до OOM** | 2-3 дня (~3GB потребления) |
| **Симптомы** | CPU скачет до 80-98%, OOM killer убивает процесс |
| **Версия** | v1.0.9 |
| **Локация** | Сервер 193.164.155.153 (Хельсинки) |

## Текущие меры

### Ежедневный перезапуск (cron)

```cron
0 4 * * * /usr/bin/systemctl restart wireproxy
```

Перезапуск в 4:00 каждую ночь не даёт памяти вырасти до критического уровня. Это предпочтительнее обновления бинарника.

### Swap

```
swap 2GB
vm.swappiness = 10
```

2GB swap добавлен для смягчения пиков потребления. `swappiness=10` гарантирует, что swap используется только при реальной нехватке памяти, а не преждевременно.

## Диагностика

```bash
# Подключиться
ssh 193.164.155.153

# Статус WireProxy
systemctl status wireproxy

# Логи
journalctl -u wireproxy -n 20

# Потребление памяти
ps aux --sort=-%mem | head
```

## План при ухудшении

1. **Проверить cron** — выполняется ли ежедневный перезапуск
2. **Обновить бинарник** — если вышла новая версия WireProxy без утечки
3. **Увеличить частоту перезапусков** — если утечка ускорилась (каждые 12ч или 8ч)
4. **Рассмотреть альтернативы** — если проблема остаётся: замена WireProxy на чистый WireGuard + iptables
